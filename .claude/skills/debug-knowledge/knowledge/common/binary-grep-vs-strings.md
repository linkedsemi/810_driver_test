# 验证"重建后的二进制是否含新内容"：`strings` 只出 ASCII，中文/UTF-8 会漏判

## 现象

改了源码（新增一条中文断言文案/日志）后，编译完用 `strings zephyr.elf | grep "<新文案>"` 自检，
**恒为 0 命中**，一度误判成"源码没被重编 / 构建缓存没生效"。

## 根因

`strings` 默认只输出**可打印 ASCII 序列**；UTF-8 中文不出现在其输出中（含多字节序列的
字节串不被视为 ASCII 字符串）。

## 判定方法 / 处理

- 改用**二进制 grep**：`grep -ac "<UTF-8 文案>" zephyr.elf`（`-a` 视二进制为文本）；
  或只挑断言/日志里的 **ASCII 片段**（变量名、格式串占位符、寄存器名）来 grep。
- 交叉印证构建是否真的重编：`ls -l --time-style=+%F_%T` 比对 `.c` 与对应 `.obj` 的 mtime，
  或用 `nm --numeric-sort` 看新增符号的链接序是否变化。
- 心法：**"grep 不到"先怀疑工具的编码/文本模式，再怀疑构建**；把判据换成"工具一定能看见的
  那部分内容"（ASCII 片段、符号、mtime）比换一个更复杂的命令更省事。
