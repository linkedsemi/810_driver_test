# 多单元同进程加载：裸名 import 的"单元本地模块"会跨单元串味

## 现象
一个加载器 / 跑批框架在**同一进程**里依次加载多个**单元**（工程、插件、子项目、模块包……），
每个单元各有自己的辅助模块。跑到中途突然抛 `ImportError`（或"常量/函数对不上号"），
报错**指向的却像是另一个单元的文件路径**；更坑的是外层只看到前面若干单元正常、后面悄无声息，
**看起来像"跑完了"**，其实后半程根本没执行。

## 根因
Python 的 `import` 以**模块名**为键缓存进 `sys.modules`，**不看它来自哪个单元目录**。
单元脚本若用**裸名** import 自己的辅助模块（如 `from dump_results import TEST_NAMES`），
第一个 import 它的单元就把它以裸名缓存下来；后到的**同名**单元再 import 就拿到**上一个人的**对象。
报错里出现的文件路径是**首个缓存者**的路径 ⇒ 极易误判成"那个单元的文件坏了"。

加载器若只对"单元脚本**本身**"用了唯一模块名做隔离（如 `importlib` 按 `_<role>_<unit>` 装载），
辅助模块仍走裸名 ⇒ **隔离不完整**，此坑照踩。

## 判定
1. 报错为 `ImportError: cannot import name X from Y`，或"拿到的对象像另一个单元的" ⇒ 先查
   `Y.__file__` **落在哪个单元** —— 若落在一个**不是你正在处理的**单元下，即本坑。
2. 在加载不同单元前后各读一次 `import Y; print(Y.__file__)`，看路径是否**停留在上一个单元**。
3. 特征信号：逐个单元单独跑都过，**连着跑**到某个单元才断；断点位置随**加载顺序**漂移。

## 处理
- 加载下一个单元**之前**，从 `sys.modules` 清掉"属于已加载单元"的条目：
  - **判据按 `__file__` 归属**：模块文件落在**单元根目录之下**的即为"单元本地"，清它；
    **共享层（如框架自己的 `common/`）不动** —— 它本就全局共享、无同名冲突，
    清掉反而会破坏单例 / 触发重复初始化。
  - **禁止按模块名硬编码清理清单**（如写死 `["dump_results", "helpers"]`）——
    清单会随新增单元悄悄失效，漏掉的恰好就是新单元。
- 清理动作放**加载入口的最开头**（每个单元加载前都跑），别只挂在某个分支里。
- 能改 import 形态时根治 = 让单元用**带命名空间 / 相对的导入**而非裸名；
  改不动时，上面的动态清理是通用兜底。
