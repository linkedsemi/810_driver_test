# I3C 高速总线：对端上拉并联消失 → 40ns 高电平拉不上去（方法学 M1 实例 #1）

> 方法学本体（M1：软件配置全对 + 硬件波形/时序异常 → 转电路层排查）见
> `embedded-debug` §3.3；本条是它的完整实例记录（原顶层 `DEBUG_ISSUES_QUICKREF.md` #1 迁入）。

## 现象
双核 I3C 对接（I3C5↔I3C6）正常工作（boot 后 16B 写读 PASS）；从机侧切走（I3C→I2C）后主机
切回 I3C，私有写/读返回 `-EIO`（reason `write:-5`），示波器看 SCL/SDA 高电平发不起来。

## 按 M1 的排查过程
1. **软件层确认全对**：固件探针在切回 I3C 后读 `PU1_PU0=0x0c000000`（PJ10/11 = IO_PULL_UP2），
   与 boot 正常态**逐位一致** → 排除 pad 配置被清/被改；I3C 控制器 `EVR` 出错但 `SER` 类型位在
   `i3c_transfer` 返回时已被驱动清空，读不到具体类型（**寄存器读不出东西 ≠ 没错误**）。
2. **确认波形问题**：SCL/SDA 高电平上升沿慢于位时间。
3. **软件侧推导电路变化**：双 I3C 对接时**两端内部上拉并联 ≈500Ω**，高速下 40ns 高电平能正常
   发出；从机切到 I2C 后其 I3C **内部上拉随功能切换消失** → 总线只剩主机单侧 ~1KΩ 挡 → RC
   上升沿超 40ns 位时间预算 → 主机主动拉高也拉不上去 → 帧错误。

## 规避（软件侧，两种任一）
1. **主机上拉调整到 ~500Ω 挡**（等效补偿对端上拉消失后的并联阻抗）。本 case 落地：
   `zephyr/drivers/pinctrl/pinctrl_lsqsh.c` 引脚配置里强制 `io_pull_write(pin, IO_PULL_UP2)`
   （UP2 = 更强的 PU1 挡），双核全 PASS。
2. **主机保持 1KΩ 挡，但加大 IO 驱动**（`drive-strength`），主动拉高弥补 RC 慢。

## 给用户（硬件）的建议方向
核对对端切走后的上拉网络、评估是否需要外部上拉电阻稳定最弱情形。

## 通用教训（归 M1）
- "切换后 / 重新使能后总线报 `-EIO`" **不一定是状态机或寄存器配置错**，先排除总线电气。
- 寄存器读出来"全对"不能证明总线没问题——**涉及总线的"动态切换后不通"，示波器/逻辑分析仪
  看波形优先级高于寄存器断点**。
- 多主/主从对接且一端会"切走"的总线拓扑（I3C/I2C 复用、热插拔、对端休眠），设计时就要算
  "最弱上拉情形"下的 RC 是否满足最快位时间。
