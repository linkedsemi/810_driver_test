# 同址并存 ⇒ PASS/FAIL 不可归因：挪址重扫判别法

> 方法学佐证：`embedded-debug` §1（分层定位）、§2（多来源变量隔离）、§3.3（寄存器全对≠总线没问题）。

## 现象
被测器件（从设备）与总线上**另一个既有器件撞在同一地址**（同址邻居）。此时读写由两个器件
**并联应答 / 争总线**，于是：
- 单项结果为**合成结果**（谁先 ACK、数据段谁驱动，看运气）；
- 表现为"**大部分对、尾部错**"这类**看似轻微**的偏差，极易被误读成"通路质量差 / 丢字节"；
- 更坏的形态：**PASS 也不可归因** —— 成功可能来自邻居而非 DUT，等于**没测到被测对象**。

## 根因
- 地址是总线的**唯一寻址键**：两个物理器件占同一地址 ⇒ 主机无法指定跟谁说话，观测是"并联体"的合成。
- **惯例地址天然高风险**：I2C EEPROM 惯例段为 `0x50`~`0x57`（`0x50` = A0-A2 全 0），
  传感器/IO 扩展器等从机地址也成片占用 ⇒ 随手挑的"空闲"地址可能**正被板上器件占用**，
  而"这个地址能 ACK"**恰恰不能证明**应答者是 DUT。

## 判定方法（怀疑撞址时的廉价判别法）
1. **把被测器件挪到一个"改址前扫描不到"的地址**：先全址扫描，挑一个**实测无人应答**的地址
   （避开惯例地址段），改址后再复测同一组用例。
2. **重扫确认唯一性**：改址后全址扫描应只剩 DUT 一个 —— 看 **`count` 与 `addrs` 两个量**，
   别只看"扫到了"（真实形态：`count=2, addrs=33 50` ⇒ 暴露了另一地址上的既有器件）。
3. **取 DUT 自身的地址寄存器作辅助证据**：如 I2C target 的 `OAR1`（`OA1EN=1` + 地址字段 = 配置值）
   ⇒ 片内 target 绑的是**新地址**，不可能是旧地址的应答者（低成本、可直证）。
4. **换址前后行为对比**：同一代码路径在新地址上由错变对（或反之）⇒ 旧地址存在干扰源。
5. **旁路通路对照**：用**不经中间器件**的通路（如滤波器旁路）读同一地址，结果不同 ⇒ 中间器件在起作用。

> **纪律**：**有同址邻居时，任何 PASS/FAIL 都不可以归因** —— 不是"可信度下降"，而是**不可用**。

## 处理
- 选测试地址时**主动避开该总线上既有器件的惯例地址**（I2C：EEPROM `0x50`~`0x57` 等成片惯例段），
  并在改址前**实测确认该地址无人应答**；不要以"惯例上应该空着"为由默认空闲。
- 一旦发现撞址：把**此前基于该地址的全部结论**标注为**不可归因**（**留痕**，不删原记录），
  挪址复测后再下结论 —— "可复现"不等于"可归因"。
- 器件自身的地址寄存器（target `OAR1` / 桥的地址配置寄存器）是**判别应答者身份**的本级证据。
