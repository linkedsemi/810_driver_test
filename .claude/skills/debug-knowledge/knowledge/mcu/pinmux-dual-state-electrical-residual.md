# 外设引脚复用双状态切换：漏声明电气属性 → 开漏残留致通信失效（mcu 域实例 #1）

> 方法学佐证：`embedded-debug` §1.3（复位域覆盖 / 本层扫描完整性）、§1.4（多来源变量隔离）。

## 现象
外设 A 与外设 B 复用同一组引脚，运行时动态切换（如 I2C↔I3C 引脚复用）；切到 B 再切回 A
后 A 通信失效——读返回 `ret=0/n=0`，波形上对端发若干字节后时序超时。

## 根因
A 态引脚节点**漏声明电气属性**（`drive-push-pull` 或 `drive-open-drain`）。pinmux 驱动在"引脚
有 push-pull 属性"时才执行推挽配置（`io_cfg_pushpull`）；缺属性则不执行。切 B 时把该引脚置为
开漏（开漏/OD 位置位），切回 A 时因无 push-pull 属性不执行推挽配置，**开漏位残留** → 驱动
能力/电平异常 → A 通信失败。

该开漏位落在独立（常开/电源）域，A 模块的复位线**不覆盖**它，只有整板/全芯片复位才清——
于是"所有软件复位都救不活"会被误判为硅级 erratum。

## 判定
1. 扫引脚节点的**完整电气属性**（`drive-*` / `bias-*` / `input-enable` 等），对比复用两个状态
   是否都显式声明；只扫功能使能/上拉下拉子集会漏判。
2. 扫**切换前后方向/电气寄存器的 diff**（方向 OE、输出值、开漏位等），不只看函数配置"看起来对"。
3. 隔离实验（embedded-debug §1.4）：换不相干同类模块不复现 ⇒ 排除系统性；断总线仍复现 ⇒
   排除总线毛刺。
4. 复位实验：读复位前后该寄存器值，不变 ⇒ 该复位未覆盖此状态（embedded-debug §1.3）。

## 处理
- **复用同组引脚的两个状态，每个状态的引脚节点都要显式声明完整电气属性**（推挽/开漏/上下拉/
  输入使能），不依赖默认值或对端状态。
- 复位救不活时先查状态所在时钟/电源域，别过早归因硬件 erratum。
