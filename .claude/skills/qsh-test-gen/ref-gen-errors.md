# 常见生成错误速查

生成后编译/烧录/运行出错时查此表（现象→根因→修法）。

| 错误 | 原因 | 修法 |
|---|---|---|
| ztest 输出不出现 | test_main 返回导致 LOG_PANIC 死窗/停摆 | `k_thread_join(K_FOREVER)`；另查 prj.conf `CONFIG_ZTEST_VERBOSE_OUTPUT=y`（`KNOWN_ISSUES.md` #26） |
| ISR 里 LOG 导致时序崩 | 违反 `SPEC_REFERENCE.md` §6.1.2 | 改记账，dispatcher 汇总打印 |
| IBI/HJ 卡死 | ISR 里调 i3c_ibi_raise（拿 mutex） | 经事件队列 |
| 编译过但烧录不跑 | overlay 缓存旧 SRAM 地址 | `rm -rf build/*` 全量重建 |
| 串口角色全 ? | 连接残留 / 口号错 | qsh-debug §2.3 / §4.1 |
| INFO 宏编译错（"macro passed N arguments" / format 警告） | variadic 宏把格式串与数值参数一起透传，格式串既拼进 fmt 又重复入参 → 参数错位 | 用公共 `ZT_INFO(name, fmt, ...)` 宏（printk 直出，见 common/ztest_glue.h），勿自造 INFO 宏 |
| run 脚本 build 失败 "source directory -D does not exist" | west build 的 `-D` 必须连写 `-DVAR=VAL`，拆开会被当 source 目录 | `["west","build","-p","auto","-b",BOARD,"-d",build, src, f"-DDTC_OVERLAY_FILE={overlay}"]` |
| cmake 报 Invalid character escape '\z' | Windows 反斜杠路径传进 cmake 被转义 | 路径统一 `.as_posix()`（正斜杠） |
| run 脚本 ValueError: too many values to unpack | token 正则 `(TGT)` 用了捕获组，groups() 多出角色组 | 固定文本用非捕获组 `(?:TGT)`，只有变量用 `(...)` |
| run 脚本 TypeError: write_text() got unexpected keyword 'mode' | Python 3.5+ 的 Path.write_text 无 mode 参数 | 用 `with open(path, "a"/"w", encoding=...)` |
| dbg_run.py / run_test.py 串口 0 行（单核工程） | 脚本漏 `set {int}0x4002200c = 2`（cpu2 hold），cpu2 自启劫持 uart1 | ★ **模板必须注入**：gdb 命令序列在 `reset` 前加 `set {int}0x4002200c = 2`（APP_CPU_SRST bit1）；所有 dbg_run.py / run_test.py 模板必须包含此步骤 |
| overlay 编译后 printk 无输出 | overlay 缺 `chosen { zephyr,console = &uart1; };`，DT_CHOSEN 为 NULL → uart_console_init 跳过 | ★ **模板 overlay 必须含 chosen 块**：单核工程 overlay 显式声明 `chosen { zephyr,console = &uart1; };`；双核 cpu2 侧走 cpu2_console_uart5.overlay |
| 测试代码 store fault 挂死 → 串口 0 行 | k_malloc 返回 NULL → memset(NULL) → 崩溃；极具迷惑性表现为"串口无输出" | ★ **测试代码禁用堆分配**：不用 k_malloc/k_calloc，改用静态数组（`static uint8_t buf[N]`）；prj.conf 不依赖 CONFIG_HEAP_MEM_POOL_SIZE；排查串口无输出时**先查崩溃再查配置** |
| run 脚本归档只有 .json 没有 .md | 模板归档段漏 `write_markdown_report` | 抄已迁移 run_test.py：md writer + update_summary 报告路径指 .md（§1.6，2026-09-08） |
| 增删测试项后 dump mem 兜底错位/假 MISSING | run_test.py 与 dump_results.py 各硬编码一份 TEST_NAMES，只改其一；新项插在链接序**前部**时旧列表整体移位一格 | **两份 TEST_NAMES 必须同改**（都是 ztest 链接序，勿用 protocol.h 枚举序，两者不一致）；构建后 `nm --numeric-sort <elf> \| grep z_ztest_unit_test` 复核全序，并同步更新两处注释里的实测序清单（2026-09-09 broadcast 漏同步 dump_results 实例） |
| 第 2 个用例起崩溃（load access fault）→ 串口从此静默 | `ZTEST_SUITE` 回调落错槽：`setup`/`teardown` 是**套件级**、`before`/`after` 是**用例级**；teardown 落进 `after` → 每例后把共享句柄置 NULL，下一例用 NULL | ★ 共享句柄一律走**套件级 `setup`/`teardown` 同层配对**；落错槽只能挪回 teardown 槽（`before/after` 形参是 `void(*)(void*)` 与 setup 的 `void*(*)(void)` 类型不通，挪不过去，见 §1.4 第 8 条） |
| 单核工程 dbg_run.py / dump_results.py / run_test.py 串口 0 行（固件像没跑） | 脚本硬编码 2os 入口 `0x100c0000`，把 `$pc` 设错 | ★ 入口走环境变量 `os.environ.get("TARGET_ROM_START", "0x10000000")`（dump_results 用 `int(...,0)`）；单核 1os = `0x10000000`、2os = `0x100c0000`（§1.5）；`run_test.py` 的 `BOARD` 单核必须 `@1os/lsqsh/cpu1` |
| dbg_run.py 角色识别全 `?` / 误报 "no firmware banner seen" | 从样板复制 dbg_run.py 时漏改 `TGT_BANNERS`/`CTRL_BANNERS`，残留上一驱动的 banner 文案（如 "CPU1 TRNG"） | 复制后改成本驱动 banner 文案 + `TESTS_DIR`（§1.5） |
| **以太网工程**编译报 `'CONFIG_NET_TCP_WORKER_PRIO' undeclared`，或链接报 `undefined reference to 'shell_fprintf_error'` | `eth_dwmac.c:73-75` 取 `CONFIG_NET_TCP_WORKER_PRIO`（`NET_TCP=n` 时未定义）；`eth_dwmac.c:832` **无条件**注册 shell 命令，`SHELL_CMD_ARG_REGISTER` 在 `SHELL=n` 下非空宏 → handler 强引用 `shell_fprintf_error`（仅 `SHELL=y` 编入） | ★ prj.conf 补 `CONFIG_NET_TCP=y` + `CONFIG_SHELL=y` + `CONFIG_SHELL_BACKEND_SERIAL=n` + `CONFIG_SHELL_BACKEND_DUMMY=y`（qsh-test-gen §1.7，参考 `projects/eth_test/cpu1_eth_test/prj.conf`） |
| 编译报 `error: expected '=', ',', ';', 'asm' or '__attribute__' before '.' token`，**列号指向注释行** | C/H 文件**块注释里出现了 `*/` 序列**（高频写法：通配路径 `case_*/`、`a*/b`）→ `*/` **提前终止注释**，其后的中文说明被当代码 | 注释内不得写 `*/`：用 `case_xxx/` 代替 `case_*/`；生成后静态检查 `*.c/*.h` 注释内的 `*/`（qsh-test-validate §1.9i） |
| 编译报 `conflicting types for 'xxx_yyy'` / `too many arguments to function 'xxx_yyy'` | `ZTEST(suite, name)` 的**实体函数名是 `<suite>_<name>`**（注册段名才用裸 name），与驱动导出符号**同名**；suite 用驱动短前缀（`spif`/`i2cf`/`spid`）时最易撞 | 改测试项名，使 `<suite>_<name>` ≠ 任何驱动导出符号名（如 `clk_check_config` → `sck_threshold_config`）；见 §1.4 第 9 条 |
| 未注册模块（不在 `zephyr/west.yml`）的源/头文件找不到，或 `EXTRA_ZEPHYR_MODULES` 要每个调用点重复传 | 模块未进 manifest，构建系统不认识它；`-DEXTRA_ZEPHYR_MODULES` 只在命令行有效 | ★ 在应用 `CMakeLists.txt` 的 `cmake_minimum_required` 之后、`find_package(Zephyr)` **之前** `set(EXTRA_ZEPHYR_MODULES "<abs>")`（`zephyr_module.cmake:39` 此刻读该变量；放之后无效）→ 三路径免传参（§1.5 / KNOWN_ISSUES #77） |
| `ZT_INFO` 报 `'<name>' undeclared (first use in this function); did you mean '<suite>_<name>'?` | `ZT_INFO(name, fmt, ...)` 的**第一参被塞进 `%s` 的位置参数**（宏体 `printk("INFO %s: " fmt, name, ...)`），属**表达式**而非名字拼接 ⇒ 传标识符即被当变量引用 | 第一参一律写**字符串字面量**：`ZT_INFO("chans_tested", "n=%u", n)`（§1.4 第 4 条；12 处同错一次暴露） |
| 使能 `spi3`/`spi4` 报 `'CONFIG_DMA_DW_LLI_POOL_SIZE' undeclared` / `__device_dts_ord_N undeclared`，或运行期越界读幅度校准数组 | `spi_dw.c:2221` 要求 `dmas` 控制器已使能；`spi_dw.c:467-469` 的校准数组由 DT 子节点生成，无子节点即空数组 | ★ overlay 加 `&dmac2 { status = "okay"; };` + `&spiN { timing-calibration-disabled; };`（§1.8 / KNOWN_ISSUES #82） |
| `--raw` 采集中途 `UnicodeEncodeError: 'gbk' codec can't encode character '↔'`，脚本 rc=1、后续 RAW 输出全丢 | `dbg_run.py` 裸 `print(ln)` 串口原始行，Windows 控制台默认 GBK，固件日志含非 GBK 字符 | 启动时 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`（或 `print` 包 `try/except UnicodeEncodeError`）（§1.5 / KNOWN_ISSUES #91） |
| 大块报告（邻接矩阵/ASYM 清单）串口侧**整行丢失 / 多行合并 / 中文乱码** | deferred log ring 被连发的大块输出撑满，超出部分**静默丢弃** | 逐行 `k_msleep(20)` 量级让 log 线程排空（间隔按段长动态调）；缓冲放 `.bss`；`LOG_PROCESS_THREAD_STACK_SIZE` 提到 2048（§1.4 第 6 条 / KNOWN_ISSUES #85） |
| 邻接/连通矩阵呈**完美下三角**（第 i 行对全部 j<i 都是 `#`），links 超物理上限 | 扫描时"驱动过的脚没还原"——`GPIO_OUTPUT_LOW` 后 `GPIO_INPUT\|GPIO_PULL_UP` 未把脚拉回高电平，后续行全读成低 | 加**还原自检闸**（每脚驱动后还原再读回自身，非基线电平即 `LOG_ERR` + 单独 FAIL）；缺闸时矩阵不可用于接线结论（§1.4 第 10 条 / KNOWN_ISSUES #86） |
| 网络工程 ztest 开机白等 ~30 s（"load 后很久才有输出"/判 no_log） | `CONFIG_NET_CONFIG_SETTINGS=y` 时 `net_config_init_by_iface()` 在网口未 up 时按 `CONFIG_NET_CONFIG_INIT_TIMEOUT`（默认 30 s）等链路 | prj.conf 加 `CONFIG_NET_CONFIG_INIT_TIMEOUT=0`（等待循环整体跳过，静态地址仍立即写入）（§1.7 / KNOWN_ISSUES #89） |
| 双核 run 脚本第一个 case 就 `[ERROR] failed to open COMxx: 'SerialCapture' object has no attribute 'baud'`，case 全 FAIL | 复制模板时 `SerialCapture.__init__` 收了 `baud` 参数却**没赋给 `self.baud`**，而 `start()` 用 `self.baud` ⇒ 每次开串口必抛 | `self.baud = baud`（复制后逐字段核对构造函数） |
| 固件加了 `ZTEST` 但报告里**看不到这些项**（执行标记还 FAILED），失败项 reason 无处归 | `run_test.py` 的 `TEST_NAMES` 硬编码，加了 `ZTEST` 没同步 ⇒ 报告只遍历自己的表（实测 trng 9 项 vs 固件 15 项、spif 15 项 vs 固件 18 项，**跑过但结果被丢弃**） | `TEST_NAMES` 从固件/COVERAGE **派生**或加一致性校验；三方核对 固件 `ZTEST(` 数 == run `TEST_NAMES` 数 == dump `TEST_NAMES` 数，顺序符合 `nm --numeric-sort \| grep _ztest_unit_test__<suite>__`（qsh-test-validate §1.10 项 n / KNOWN_ISSUES #50/#60） |
